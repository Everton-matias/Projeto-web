\chapter*{Resumo}

Este módulo compreende a arquitetura de segurança, controle de sessão e consumo da API de Autenticação do Google no Front-End do sistema Not Fat. Desenvolvido em React.js, o sistema utiliza o padrão de Contexto Global (Context API) combinado com persistência local para garantir que o fluxo de login seja seguro, transparente e performático.

A principal função desta estrutura é validar a identidade do usuário através dos tokens emitidos pelo Google, gerenciar o estado global de autenticação e interceptar rotas protegidas no ecossistema do cliente (Front-End), trabalhando em total sincronia com as validações de segurança executadas no Back-End.

Basicamente, a arquitetura de autenticação fornecida subdivide-se em:

- Gerenciamento de Ciclo de Vida do Token: Armazenamento, leitura inicial e expurgo dos dados de autenticação sincronizados com o Google.

- Barreiras de Navegação (Middleware de Rotas): Bloqueio programático de componentes baseado no estado dinâmico de login.

- Consumo de Claims e Identidade: Estruturação das propriedades de identificação do usuário (idUsuario, email, nome) para persistência e requisições seguras.

\chapter{Estrutura e Fluxo de Autenticação }

\section{Contexto de Autenticação (AuthProvider)}

O mecanismo centraliza as operações de login e logout, servindo como uma fonte única de verdade (\textit{Single Source of Truth}) para a identidade do usuário na aplicação. 

Persistência em Cache (localStorage): O estado inicial do usuário é avaliado através de uma função de inicialização preguiçosa (lazy state initialization) que busca a chave @NotFat:user. Isso evita a perda de sessão quando a página é atualizada. Se o dado estiver corrompido ou ausente, o estado falha silenciosamente para null.

Sincronização Baseada em Efeitos (useEffect):
Monitorea o ciclo de vida do objeto user. Sempre que houver uma alteração (como o gatilho de login ou logout), o efeito colateral atualiza o armazenamento local, inserindo a string JSON correspondente ou removendo a chave por completo.

Gatilho de Entrada (signin(userData)):
Função responsável por receber o objeto de dados encapsulado após a validação bem-sucedida do token do Google e injetá-lo no estado ativo da aplicação.

Gatilho de Saída (signout()):
Limpa completamente o estado do usuário (null), o que dispara o efeito colateral de remoção dos dados do localStorage, invalidando imediatamente a sessão do cliente.

\section{Filtros e Proteção de Rotas}

O sistema delega a segurança visual e o controle de acesso às rotas através de validações condicionais em tempo de execução.

Prevenção de Acesso Duplo ao Login:
Um efeito colateral monitora se um usuário já autenticado tenta forçar a navegação para a página /login. Caso isso ocorra, o React Router realiza um redirecionamento limpo com substituição de histórico (replace: true) de volta para a raiz (/), impedindo comportamentos inconsistentes na interface.

Barreira de Segurança (PrivateRoute):
Atua como um componente de ordem superior (Higher-Order Component). Ele consome os dados do useAuth() e realiza uma checagem binária:

Se o objeto user não existir, ele interrompe a renderização dos componentes filhos e dispara uma navegação forçada para a rota /login.

Se o usuário estiver ativo, ele concede acesso total e renderiza o conteúdo protegido da aplicação (children).
