\chapter*{Resumo}

Este módulo compreende a arquitetura do componente de navegação global (\textit{Sidebar/Navbar}) do sistema Not Fat. Desenvolvido em React.js utilizando a biblioteca \texttt{react-router-dom} para o gerenciamento de rotas e o ecossistema \texttt{lucide-react} para a renderização de elementos visuais (ícones), o componente atua diretamente na responsividade estrutural e na indicação visual do estado dinâmico da aplicação.

A principal função desta estrutura é mapear a localização atual da URL no cliente, processar as condicionais de ativação estética dos links de navegação e acoplar as ações de encerramento de sessão de usuário através da integração nativa com o Contexto de Autenticação (\texttt{AuthContext}). O design do componente é baseado no framework utilitário Tailwind CSS, assegurando alta performance de renderização e adaptabilidade móvel.

Basicamente, o escopo do componente subdivide-se em:

- \textbf{Rastreamento de Rotas}: Leitura do histórico de navegação para a determinação precisa do contexto de uso do cliente.

- \textbf{Estilização Condicional Proativa}: Geração de classes utilitárias em tempo de execução para diferenciar caminhos ativos e inativos.

- \textbf{Controle de Acessibilidade e Identidade}: Implementação de tags \textit{ARIA} e tratamento resiliente das propriedades de identidade para exibição do perfil de usuário logado.

\chapter{Estrutura e Lógica de Navegação}

\section{Análise do Fluxo Interno do Componente}

O componente \texttt{Navigation} opera de maneira declarativa e reativa, sendo re-renderizado sempre que há uma transição de rotas gerenciada pelo ecossistema do cliente. A lógica interna está estruturada da seguinte forma:

\begin{enumerate}
    \item \textbf{Consumo de Contexto (useAuth)}: O componente intercepta o estado global do usuário (\texttt{user}) e a função de deslogar (\texttt{signout}) de dentro do \texttt{AuthContext}, permitindo condicionar interfaces com base no privilégio de sessão atual.
    \item \textbf{Interceptação de URL (useLocation)}: Através do hook \texttt{useLocation()}, o sistema lê o objeto \texttt{pathname}, permitindo varrer sub-rotas usando validações de prefixo através do método nativo do JavaScript \texttt{.startsWith()}.
    \item \textbf{Cálculo de Aba Ativa}: Um fluxo condicional determina uma string chave indicadora (\texttt{"inicio"}, \texttt{"agua"}, \texttt{"perfil"}). Essa abordagem centraliza o controle visual e desacopla a verificação rígida da URL nas tags do menu.
\end{enumerate}

\section{Mapeamento da Lógica de Abas e Rotas}

Para garantir que o menu lateral reflita com precisão em qual área o usuário está navegando, o componente mapeia o \texttt{pathname} em grupos de interesse lógico, conforme detalhado na tabela abaixo:

\begin{table}[H]
\centering
\renewcommand{\arraystretch}{1.4} 
\begin{tabular}{|p{3.0cm}|p{6.0cm}|p{3.5cm}|}
\hline
\textbf{Estado Ativo}& \textbf{Condição Logica (URL)}& \textbf{Escopo Visual Afetado}\\ \hline

\texttt{"perfil"}& 
\small{\texttt{/profile}}, \small{\texttt{/profile/*}}, \small{\texttt{/editar-perfil}} ou \small{\texttt{/editar-perfil/*}}& 
Link de acesso aos dados do usuário e configurações.\\ \hline

\texttt{"agua"}& 
Inicia com \small{\texttt{/agua}}& 
Módulo de acompanhamento do diário de hidratação.\\ \hline

\texttt{"inicio"}& 
Default (Qualquer outra rota / Raiz \small{\texttt{/}})& 
Painel principal (\textit{Dashboard}) da aplicação.\\ \hline
\end{tabular}
\label{tab:rotas}
\end{table}

\section{Geração de Classes Dinâmicas (Tailwind CSS)}

A customização visual dos botões é encapsulada na função de ordem interna \texttt{itemClass(ativa)}. Esta função recebe a identificação da aba avaliada e executa uma operação ternária de comparação contra o estado \texttt{abaAtiva}.

\begin{itemize}
    \item \textbf{Se ativo}: Injeta classes de destaque como opacidade total de texto (\texttt{text-white}), sombreamento interno para simular bordas de relevo (\texttt{shadow-[inset...]}) e fundo levemente clareado (\texttt{bg-white/10}).
    \item \textbf{Se inativo}: Aplica uma estilização discreta com opacidade reduzida (\texttt{text-green-100/90}) e efeitos de transição suave (\texttt{duration-200}) acionados durante o evento de \textit{hover}.
\end{itemize}

\section{Tratamento de Exibição e Fallbacks de Identidade}

O bloco inferior do componente é uma zona restrita que monitora o encerramento da sessão. Ela implementa regras rígidas de segurança visual baseadas em duas verificações simultâneas: a existência do objeto \texttt{user} e a validação se a página atual é a de edição de perfil (\texttt{isEditProfilePage}).

Para exibir as informações do usuário de forma segura e sem gerar quebras de renderização (\textit{runtime errors}), o sistema adota um padrão de recuperação (\textit{fallback}) em cascata de strings prioritárias:

\begin{lstlisting}[language=JavaScript]
{user.nome_completo || user.name || user.email}
\end{lstlisting}

O compilador avalia as expressões da esquerda para a direita. Caso o campo estruturado pelo banco de dados (\texttt{nome\_completo}) esteja ausente, ele consome a claim padrão da API (\texttt{name}). Se ambas estiverem nulas, o sistema renderiza o \texttt{email} do usuário como o identificador definitivo da interface.
